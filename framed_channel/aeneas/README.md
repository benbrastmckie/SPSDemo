# aeneas/

The Lake package that connects the hand-written models in `../lean` to a real Charon/Aeneas
extraction of the whole `../rust` crate. All nine units are extracted, axiom-free, and bridged to
their models: the ring buffer, the list-backed `VecQueue`, the varint codec, the zigzag
signed-varint codec, the CRC-8 and the HDLC byte-stuffing codec, with the specification's laws
instantiated directly on their extracted carriers, and the channel, whose composition theorems are proved once over any lawful extracted
queue record and instantiated at both queues. The package requires the Aeneas Lean library at the currently pinned revision (see
`../../nix/aeneas-pin.json`'s `rev`; `aeneas_rev_coherence` checks it against `flake.lock` and
this package's own `lake-manifest.json`) and the core package `../lean` by path, on the same
`lean-toolchain`, so Lake reuses `../lean/.lake/build`.

## Two layers: extracted and bridge

```
┌───────────────────────────────────────────────────────────────────┐
│ Registry.lean        bridge rows, hash-bound; allItems / allBank  │
└──────────────────────────────┬────────────────────────────────────┘
                               │ registers theorems of
┌──────────────────────────────┴────────────────────────────────────┐
│ Bridge/       HAND-WRITTEN: relates the extraction to ../lean     │
│   Queue/     Defs         definitions: QueueSim, Ext, records     │
│              Traits       assumptions on Defs' Default/Clone      │
│                            records (`dflt`, `cln`)                │
│              Transport    six transport theorems                  │
│              Instance     laws on Ext from any QueueSim           │
│   Std.lean                    step specs the library lacks        │
│   RingBuffer/                 Defs, Refinement, Instance          │
│   VecQueue/                   Defs, Refinement, Instance          │
│   Varint/                     Defs, Encode, Decode, Instance      │
│   Crc8/                       Defs, Bitwise, Table, Instance      │
│   Channel/                    Defs, Abstraction, Frame,           │
│                               Refinement, Composite, Instance     │
└──────────┬───────────────────────────────────────┬────────────────┘
           │ about                                 │ stated against
┌──────────┴────────────────────────┐  ┌───────────┴────────────────┐
│ Extracted/  GENERATED, never      │  │ ../lean  Spec/ laws and    │
│ edited: Types, Funs (plus the     │  │ Model/ reference models    │
│ hand-written FunsExternal)        │  │ (no Aeneas, no Mathlib)    │
└───────────────────────────────────┘  └────────────────────────────┘
```

- **Extracted** is what Charon and Aeneas produce from `../rust`, regenerated by
  `../scripts/refresh-extraction.sh` and checked for staleness by `../check.sh`.
- **Bridge** is where every claim about the extracted code is made. The laws are stated once, over
  the specification's own `Result`, in `../lean/FramedChannel/Spec/`, and never restated for an
  extracted carrier. Each interface has one simulation structure (`QueueSim` for queues) with
  generic transport theorems proved once, and each component proves one simulation from its
  refinement theorems: the claim shape `Faithful impl model -> Refines model spec -> Refines impl
  spec`, with `Faithful := QueueSim` and `Refines model spec := BoundedQueueLaws`.
- **Registry** binds every certified bridge theorem to its statement hash, as the core registry
  does.

As in `../lean`, every definition a registered statement mentions lives in `Bridge/Queue/Defs.lean`
or a component's `Bridge/<X>/Defs.lean`, so the Challenge library can import it without importing
a registered theorem. Loop invariants no statement mentions stay beside their proofs.

**Namespaces.** Bridge declarations live under `FramedChannel.Bridge`, in sub-namespaces that
follow the extraction's snake_case module names (`ring_buffer`, `varint`, `crc8`, `channel`),
except `vec_queue`, named after the type because its module `queue` also holds the trait. The
generic queue bridge sits in `FramedChannel.Bridge` itself. Never state a bridge theorem in a
`FramedChannel.RingBuffer.*` or `ring_buffer.*` namespace: it would capture the model's or the
extraction's own names. `Registry.lean` records the convention.

**The Challenge library**, `FramedChannelAeneasChallenge/` (root
`FramedChannelAeneasChallenge.lean`, modules `Queue`, `RingBuffer`, `VecQueue`, `Varint`, `Zigzag`,
`Stuff`, `Crc8`, `SeqNum`, `Channel` and `StuffedChannel`; not a default target), restates every
registered bridge theorem with `:= sorry`, importing only `Defs` modules: the approved bridge
specification, one approval unit per module (`Queue` holds the component-independent transport
theorems and `cloneVecU8_isId`). See `../certificate/README.md`, "Select, Specify and approval".

## Cost

The Aeneas Lean library requires Mathlib. The first build needs network access and about 7 GB
under `.lake/` (ignored by git), and compiles the Aeneas library in a few minutes. `../check.sh`
builds and audits this package on every gate run (fetching the dependencies if they are absent);
`--core-only` leaves it out and ends INCOMPLETE, which is not the verification claim.

```
lake exe cache get && lake build       first build, from this directory
bash ../check.sh                       the gate, including this package
```

## The layout rule

The same rule as `../lean` (stated in full in `../lean/README.md`), in this package's vocabulary:

**`Bridge/` is a unit layer, so it holds one `Bridge/<Unit>/` directory per unit.**
`Bridge/<Unit>/Defs.lean` holds definitions only and is the only module of that unit a Challenge
module may import; proof modules are named for what they prove and end at `Instance.lean`, where
the interface instance on the extracted carrier is built.

`Bridge/Queue/` is a unit directory like any other: `Defs.lean`, `Traits.lean`, `Transport.lean`,
`Instance.lean`. Its "unit" is the `BoundedQueue<T>` interface rather than a concrete type, which
is why its contents are generic, but it is laid out identically and no special case for it
survives in `../check.sh`.

**`Bridge/Std.lean` is the single exception, and it is what a flat module under a unit layer
means**: package-level infrastructure owned by no unit. It holds `@[step]` specifications of
*Aeneas's own* library definitions, shared by the Varint, Crc8 and Channel bridges. Its own header
says so. A new flat module under `Bridge/` is a mistake unless it is infrastructure of the same
kind.

`Extracted/` is not a unit layer at all: it is generated output plus the one hand-written
`FunsExternal.lean`.

## Modules

### FramedChannelAeneas/Extracted/Types.lean, Funs.lean
Generated by `../scripts/refresh-extraction.sh` (one whole-crate `charon cargo --preset=aeneas` run, then
`aeneas -backend lean -split-files -all-computable`) and never edited; no `axiom`. They hold, in
Aeneas's `Result` monad:

- `queue.BoundedQueue Self T`: the trait as a record of its eight methods, each `&mut self` method
  returning the updated `Self`; each `impl` is a record value whose `Default`/`Clone` bounds are
  explicit record parameters;
- `queue.VecQueue T` and `ring_buffer.RingBuffer T` with their methods, over `alloc.vec.Vec` and
  `Std.Usize`;
- `varint.encode_u32`/`decode_u32` and `crc8.crc8`/`crc8_table`, each loop as a `_loop.body` plus a
  `_loop` over Aeneas's `loop` combinator;
- `channel.Channel Q`, whose `with_queue`, `send`, `deliver`, `take` and `queued` take the
  `queue.BoundedQueue Q (Vec U8)` record explicitly; `channel.ChannelRingBufferVecU8.new`; and
  `parse_frame`, `encode_frame`, `drop_front`;
- the derived `Debug`/`Clone`/`PartialEq` impls.

### FramedChannelAeneas/Extracted/FunsExternal.lean
Hand-written: the crate's trusted library models for the five functions the crate calls but the
pinned Aeneas library does not model. Each is a definition (never an axiom) with its `rust_fun`
attribute and a citation of the Rust semantics:

- `Option`'s `Try::branch` and `FromResidual::from_residual` (the `?` operator on `Option`, in
  `parse_frame`);
- `<[T]>::split_first` (`parse_frame`);
- `Vec::remove` (`VecQueue::pop`; panics when `index >= len`);
- `<Vec<T> as Default>::default` (needed by `Channel::new`'s `RingBuffer<Vec<u8>>`).

Four proved `@[step]` specs accompany them (`from_residual` needs none: its only residual is
`None`). A spec proves a property of the Lean definition; that the definition models the Rust
function is trusted, as Aeneas's own library models are.

### FramedChannelAeneas/Bridge/Queue/Defs.lean, Queue/Traits.lean
`Queue/Defs.lean` holds the queue-side definitions: the canonical `Default`/`Clone` records and
`CloneIsId`, the simulation structure `QueueSim`, and the extracted carrier `Ext` with its lowered
operations and `QueueModel` instance. `Queue/Traits.lean` shows `CloneIsId` is satisfiable and proves it
(`cloneVecU8_isId`) for the derived `Clone` of `Vec<u8>` the extraction uses for frames, so no
theorem about a queue of frames carries it as a hypothesis.

### FramedChannelAeneas/Bridge/Queue/Transport.lean
Over `QueueSim S Q T inst R` (defined in `Queue/Defs.lean`): the extracted record `inst` simulates
a `QueueModel` `Q` through a
relation `R`, one field per method and branch, each an Aeneas triple. The six transport theorems
(`push_law_of_sim`, `pop_law_of_sim`, `full_law_of_sim`, `empty_law_of_sim`,
`not_full_of_lt_of_sim`, `push_capacity_of_sim`) prove, once for every queue, that a simulating
record satisfies each law read through `R`.

### FramedChannelAeneas/Bridge/Queue/Instance.lean
Proves `BoundedQueueLaws` on `Ext S Q T inst R` (`{s : S // ∃ q, R s q}`, defined with its
`QueueModel` instance in `Queue/Defs.lean`, running the extracted methods through `Result.match`)
from any `QueueSim` whose relation is functional; `QueueSim.boundedQueueLaws` proves all six laws
on `Ext`.

### FramedChannelAeneas/Bridge/Std.lean
Eight `@[step]` specifications of Aeneas library definitions the pinned library leaves
unspecified: `i32` range iteration, `Slice.get` at a `usize`, `RangeFrom` and `RangeTo`, the slice
iterator, `u32::from(u8)`, `Vec::extend_from_slice` (under an identity `Clone`) and
`usize::saturating_sub`. Each is a theorem about a library definition, never an assumption, and
none touches the library's `get_unchecked` axiom.

### FramedChannelAeneas/Bridge/RingBuffer/
`Defs.lean`: the abstraction function `toModel` (each `Vec` to its `List`, each `Usize` to its
`Nat`) and the carrier `ExtractedRB`. `Refinement.lean`: error agreement
(`push_full`/`pop_empty`), `push_refines`/`pop_refines` under `Inv`, observer agreement
(`capacity_agrees`, `is_full_agrees`, `is_empty_agrees`, `len_agrees`), `sim`,
`with_capacity_rel` (the `with_capacity` constructor, bridged separately from the `QueueModel`
operations), and
`push_law_extracted`/`pop_law_extracted`. `Instance.lean`: `carrier_iff_inv` and
`instBoundedQueueLaws_extracted`.

### FramedChannelAeneas/Bridge/VecQueue/
`Defs.lean`: `toModel` to `VecQueue.VQ` and `ExtractedVQ`. `Refinement.lean`: error agreement,
`push_refines` (no hypothesis: the overflow bound follows from `len < cap <= usize::MAX`),
`pop_refines`, the observer agreements, `sim` and `with_capacity_rel`, at every `Clone`
record.
`Instance.lean`: `instBoundedQueueLaws_extracted`, with no trait assumption.

### FramedChannelAeneas/Bridge/Varint/
`Defs.lean`: `bytesOf` (machine bytes to `Nat`) and the extracted codec's `CodecModel` instance.
`Encode.lean`: `encode_refines`, by a loop lemma over `loop.spec_decr_nat`. `Decode.lean`:
`decode_refines`, whose postcondition `DecPost` splits on the result (`Err` is a model failure or a
model value at or above `2^32`, the Rust's stricter `Overlong`). `Instance.lean`:
`decode_ok_refines`, `decode_complete`, `decode_err_iff`, the hypothesis-free
`roundtrip_extracted` over `Std.U32`, and `instCodecLaws_extracted`.

### FramedChannelAeneas/Bridge/Crc8/
`Defs.lean`: `bitsOf` (machine bytes to `BitVec 8`) and the two extracted `ChecksumModel`
instances. `Bitwise.lean`: `crc8_refines`, through the inner and outer loops. `Table.lean`:
`table_agrees` (kernel `decide`), `table_index` (the lookup is always in range) and
`crc8_table_refines`. `Instance.lean`: `crc8_table_eq_extracted` and the `ChecksumLaws` instances
on `ExtractedBitwise` and `ExtractedTabled`. No `bv_decide` anywhere in the bridge.

### FramedChannelAeneas/Bridge/Channel/
Stated once over any lawful extracted queue record. `Defs.lean` gives the frame carrier at
`Vec<u8>`, the relation `ChanRel` between an extracted channel and `Chan (Ext ...)`, and the other
definitions the statements mention (`DeclaresWideLength`, `ParsePost`, `ChanRB`/`ChanVQ`);
`Abstraction.lean` keeps the byte and carrier lemmas. `Frame.lean`: `encode_frame_refines` and
`parse_frame_refines` (the one divergence, a declared length of `2^32` or more, stated in
`ParsePost`), `drop_front_refines`, the extracted round trip and `parse_frame_len126_extracted`.
`Refinement.lean`:
`send_refines`, `deliver_refines`, `take_refines`, `queued_agrees`; `send_refines` keeps two
genuine hypotheses, room on the wire and `len + in_flight <= usize::MAX`. `Composite.lean`: the core
composition theorems at the extracted carrier, with `ChanInv` discharging the overflow hypothesis
(`hovf_of_inv`) and `not_declaresWide_encodeFrame` ruling out a declared-length divergence for an
in-range frame. `Instance.lean`: two of the six core Composite theorems, `send_deliver_extracted`
and `deliver_spec_extracted`, instantiated at the ring-buffer and `VecQueue` records (the other
four hold at either record already through the generic carrier, with no separate instance
needed); `with_queue_idle`/`with_queue_idle_VQ` (an idle queue after `Channel::with_queue`, so no
idle
state is assumed elsewhere); and
`send_deliver_from_new_RB`/`_VQ` starting at `Channel::new` / `Channel::with_queue`.

### FramedChannelAeneas/Bridge/Stuff/
The HDLC byte-stuffing codec, the one whose error agreement is an exact `iff`. `Defs.lean` gives the
byte abstraction `bytesOf`, the extracted codec tag `ExtractedHdlc` and its lowered
`extEncode`/`extDecode`. `Stuff.lean`: the extracted-constant value lemmas, `stuff_loop_refines` and
the two public triples `stuff_refines` and `encode_frame_refines`, each with a room-for-two-bytes-
per-input-byte hypothesis. `Unstuff.lean`: `unstuff_loop_refines` over the accumulating decoder and
the three decode triples derived from it -- `decode_ok_refines`, `decode_complete` and
`decode_err_iff`, the last an exact `iff` where the varint codec's is an implication in one
direction only -- plus `roundtrip_extracted`. `Instance.lean`: `instCodecLaws_extracted`.

### FramedChannelAeneas/Bridge/StuffedChannel/
The transparent composite, stated once over any lawful extracted queue record, exactly as
`Bridge/Channel/` is. It reuses that directory's frame and queue plumbing rather than mirroring it
(the frame carrier at `Vec<u8>`, `FrameVec`, `ExtQ`, `rbRecord`, `vqRecord`); what it declares of
its own is the wire. `Defs.lean`: the relation `SChanRel`, `DeclaresWideLength`, `ParsePost` and
`SChanRB`/`SChanVQ`. `Abstraction.lean`: the two byte views (the model's wire is `List Nat`, payload
frames are `List (BitVec 8)`) and the three component-tag spellings. `Frame.lean`: `body_refines`,
`encode_stuffed_refines`, `parse_stuffed_refines` and the extracted round trip;
`parse_stuffed_refines` carries no hypothesis at all, arithmetic included, and its `ParsePost` has
exactly one divergence disjunct, the varint layer's -- the stuffing layer contributes none.
`Refinement.lean` and `Composite.lean` mirror the channel's, and `Composite.lean` adds
`wire_flag_free_extracted`, the transparency claim on the extracted side. `Instance.lean`
instantiates everything at both extracted records, the substitution row at a second composite.

### FramedChannelAeneas/Bridge/Zigzag/, Bridge/SeqNum/
Not yet described here. Both are registered, bridged and certified (`../certificate/zigzag.yaml`,
`../certificate/seq_num.yaml` name every row); only these navigation entries are missing, and they
belong to whichever change next touches those units.

### FramedChannelAeneas/Registry.lean
The bridge registry, through core `Certify.lean`'s `register%`: every certified bridge theorem
bound to its statement hash. `allItems`/`allBank` concatenate the core registry and this one, with
row count and score totals closed by kernel `decide`. Regenerate both hash columns with
`bash ../scripts/refresh-hashes.sh --aeneas`.

### GenVectors.lean
The differential-vector generator, outside the library (it states no obligation).
`lake env lean --run GenVectors.lean` evaluates the extracted definitions -- both queue records at
`u32`, the codec, both checksums, the frame codec, and `Channel<Q>` through `Channel::new` and
`Channel::with_queue` -- and prints the records `../certificate/vectors.txt` holds, observing
Aeneas's `Result` through `Result.match` and recording a failed evaluation as `panic <error>`. It
runs interpreted, so nothing is compiled natively. `../scripts/refresh-vectors.sh` is its only writer. The
values are the interpreter's, not kernel reductions (the extracted `loop` is a `partial_fixpoint`).

## How the extraction differs from the models

| Difference | Model | Extraction | Discharged by |
|---|---|---|---|
| Containers | `List` with `getD`/`set` | `alloc.vec.Vec` with its own index lemmas | abstraction functions (`Vec` to `List`, bytes to `Nat` or `BitVec 8`, `ChanRel` for the channel) |
| Integers | `Nat`, with bounds as hypotheses (`n < 2 ^ 32`) | `U32`/`Usize` with overflow-checked operations | `step*` under the invariant; the varint bound becomes the type `Std.U32`; the channel's two non-local obligations stay visible (one hypothesis, one discharged by `ChanInv`) |
| Errors | the specification's `Result` | Aeneas's `Result`; `push` returns `(Err(Full), self)` | `QueueSim`, branch by branch, with no wrapper type |
| Loops | structural recursion on fuel | `_loop.body` over the `loop` combinator | loop lemmas over `loop.spec_decr_nat` whose invariants relate loop state to the model |
| Trait dispatch | type classes | a record of function fields passed explicitly | a `QueueSim` per record; the channel bridge stated over any such record, then instantiated |

## Keeping it current

The generated docstrings carry source line numbers, so any edit under `../rust/src`, a comment
included, makes `Types.lean`/`Funs.lean` stale; `../check.sh` reports that when charon and aeneas
are on PATH. From the repository root, regenerate and re-read the diff:

```
nix develop .#extraction --command bash framed_channel/scripts/refresh-extraction.sh
bash framed_channel/scripts/refresh-vectors.sh
```

**External functions.** Aeneas lists every library function it does not model in a
`FunsExternal_Template.lean` and makes `Funs.lean` import `Extracted/FunsExternal.lean`, which is
hand-written; the script never writes it or copies the template. It fails when the template's set
of `rust_fun` names differs from the set `FunsExternal.lean` defines, printing both:

- a **new name** means a Rust edit introduced an unmodeled external. Resolve it with an idiomatic
  rewrite within the modeled subset, a definition with a proved spec in `FunsExternal.lean`, or a
  refactor; never an axiom;
- a **vanished name** means an Aeneas bump now models that function: delete the local definition.

Signature drift within a name is caught by the Lean build. The script, and the gate's bridge stage,
also fail on any `axiom`, `sorry`, `admit` or `native_decide` in `FunsExternal.lean`. The
`-all-computable` flag keeps `Funs.lean` out of a `noncomputable section`, which Aeneas otherwise
emits when external definitions are present.

**Pins.** `../scripts/lib/aeneas-revs.sh` (sourced by `../check.sh` and `../scripts/refresh-extraction.sh`) requires
`.nodes.aeneas.locked.rev` in the root `flake.lock`, the `aeneas` revision locked in
`lake-manifest.json` (pinned in `lakefile.toml`) and `aeneas -version` to agree; `lean-toolchain`
here to equal `../lean/lean-toolchain`; and, when charon is on PATH and the Aeneas sources are
fetched, `charon version` to match Aeneas's charon pin. To move Aeneas, update them together, run
`lake update aeneas`, regenerate the extraction, and re-run the gate (`bash ../check.sh`).
